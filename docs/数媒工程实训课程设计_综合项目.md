# 数媒工程实训课程设计题目

## 一、总体说明

本课程设计以“可运行 Demo + 技术报告 + 项目展示”为基本目标。每组围绕一个真实应用场景，完成一个可交互、可测试、可解释的 AI Agent 系统。

项目采用 **5—6 人小组开发**。每组共用一个 Git 仓库，完成需求分析、系统设计、前后端开发、Agent 编排、数据库与知识库接入、测试修复和最终交付。项目不能只有聊天页面或静态展示，必须形成一条可以实际运行的业务闭环。各方向的基本要求按约 4 天并行开发配置，进阶要求在基本业务闭环稳定后选做加分。

每个项目至少包含：

- 前端页面和后端 API；
- 用户注册、登录、退出和权限校验；
- 数据库，用于保存用户、项目、任务、会话或业务数据；
- 知识库、Embedding 向量化和检索功能；
- 至少一个 Agent，以及至少 3 个工具或工作流节点；
- 真实或人工整理的测试数据；
- 正常流程、失败流程和异常处理记录。

可使用 AI 编程工具辅助开发，但最终评价重点是场景理解、Agent 流程设计、工具调用、数据验证、失败处理、工程协作和产品化优化能力。

## 二、小组协作与 Git 要求

### 1. 小组要求

每组 5—6 人，建议设置以下角色：产品与项目负责人、前端开发、后端开发、Agent/工作流开发、数据/CV/媒体开发、测试与交付。5 人小组可以合并测试角色，但每位成员必须有实际代码、文档或测试产出。

### 2. Git 要求

1. 项目从空目录初始化 Git 仓库；
2. 每位成员使用自己的 Git 用户名和邮箱提交；
3. 使用功能分支开发，再合并到 `develop` 或 `main`；
4. 每位成员至少完成 5 次有效提交，小组总提交不少于 25 次；
5. 提交信息应说明完成内容，例如：

```text
feat(auth): 完成注册登录接口
feat(agent): 增加知识库检索工具
fix(task): 修复任务失败状态未保存问题
test(api): 增加权限校验测试
docs(readme): 补充启动和部署说明
```

6. 禁止由一个账号代替全组提交，禁止最后一次性提交全部代码；
7. 最终版本创建 Git Tag，例如 `v1.0.0-final`；
8. 提交 `.git` 目录，或提交以下 Git 记录：

```text
git_log.txt
git_shortlog.txt
git_branches.txt
git_tag.txt
```

## 三、统一提交要求

1. 项目完整交付包，包含可运行的 Agent Demo 或 Web 演示界面、项目源代码、配置文件、依赖文件、启动说明等
2. **工程实训报告（电子版和纸质版，纸质版按照学院的模板进行编写），包含：**
   - **需求分析；**
   - **用户画像和业务流程；**
   - **系统架构和数据库设计；**
   - **Agent 工作流、Prompt 和工具设计；**
   - **知识库与向量检索设计；**
   - **功能模块说明；**
   - **测试报告和失败案例分析；**
   - **项目总结与成员分工。**
3. 答辩 PPT，展示项目背景、技术方案、实现过程、Agent 调用链路、测试结果和运行效果；
4. 全程运行录屏，建议配语音讲解；
5. **项目进度日志，记录每日工作内容、Git 提交、问题和解决方案；**
6. 效果截图至少 3 张，必须包含核心功能和最终结果。

## 四、统一技术参考

- Agent：Coze、Dify、LangChain、LangGraph、CrewAI；
- 大模型：DeepSeek 或其他可用模型 API；
- 后端：Python、FastAPI 或 Flask；
- 前端：HTML/CSS/JavaScript、Streamlit；
- 数据库：MySQL、MongoDB；
- 知识库：RAG、Embedding；
- 视觉与媒体：YOLO、OpenCV、FFmpeg、Pillow；
- 数据采集：requests、BeautifulSoup、公开 API、CSV/Excel 数据整理；
- 数据可视化：Pandas、Plotly、Matplotlib、ECharts；
- 工程能力：REST API、文件上传、任务状态、日志、异常处理和 Git 协作。

各项目必须在报告中说明每项技术的用途、输入输出和局限，不能只罗列技术名称。

## 五、评分建议

| 评分项目 | 比例 | 说明 |
|---|---:|---|
| 场景与产品完整性 | 15% | 场景具体，用户流程完整，Demo 能闭环运行 |
| Agent 流程与工具编排 | 25% | 任务拆解、状态流转、工具调用和人工确认是否合理 |
| 数据与知识库实现 | 15% | 数据来源可追溯，知识库、向量化和检索结果可验证 |
| 工程实现稳定性 | 20% | 前后端、数据库、接口、权限、异常和日志是否稳定 |
| 测试评估与优化 | 15% | 成功案例、失败案例、错误来源和迭代过程是否清楚 |
| 展示与报告 | 10% | PPT、报告、演示、分工说明和技术反思是否完整 |

## 六、课程设计题目

## 1. 基于 YOLO+Agent 的智能数字媒体内容理解系统

### 项目目标

面向游戏录屏、短视频或数字媒体素材，使用 YOLO/OpenCV 完成画面目标识别和关键帧分析，再由 Agent 结合知识库生成内容摘要、标签、审核建议或素材使用建议。

### 基本要求

1. 支持图片或视频上传；
2. 使用 YOLO 输出目标类别、置信度和检测框；
3. 使用 OpenCV 对视频采样并生成关键帧；
4. 保存检测结果、证据图片和 JSON 分析报告；
5. Agent 能根据视觉结果生成摘要、标签和建议；
6. 知识库至少包含一类数字媒体规范、角色设定或素材分类规则；
7. 页面支持查看原始素材、检测结果、任务状态和历史记录；
8. 处理模型缺失、格式错误、空文件和推理失败；
9. 训练自定义 YOLO 模型识别游戏角色、道具或数字媒体设备；
10. 增加画面变化、运动强度和目标数量评分；
11. 支持内容通过、待复核和不通过三种审核状态；
12. 支持导出审核包或素材分析报告；
13. 对检测类别、置信度、关键帧时间和审核状态进行统计；
14. 使用 Plotly、Matplotlib 或 ECharts 展示目标数量、置信度分布和视频时间段分析；
15. 采集或整理不少于 30 条素材元数据，保存来源、类别、标签和处理结果；
16. 支持多模型或多阈值对比，并输出 Precision、Recall 或 mAP 对比图；
17. 增加目标跟踪，展示目标在视频中的运动轨迹；
18. 支持自动生成带图表的 HTML/PDF 分析报告。


### 技术参考

YOLO、OpenCV、FastAPI、数据库、RAG、Embedding、FAISS/Chroma、LangChain/Coze/Dify、Vue 或 Streamlit。

### 数据与测试要求

准备不少于 20 张图片或 3 个视频样例，至少展示 5 个成功检测案例和 3 个失败或低置信度案例。CV 方向提交模型权重或权重下载说明。


## 七、统一说明

1. 每组只选择一个题目，不能只做单一聊天接口；
2. 所有项目必须有前端、后端、数据库、登录注册、知识库和 Agent 主流程；
3. Agent 至少调用 3 个工具、模型或工作流节点，并保存调用日志；
4. 涉及真实平台、商品、地点、简历、评论和数据文件时，应进行隐私保护、版权合规和来源说明；
5. 推荐使用 FastAPI + HTML/CSS/JavaScript 或 Vue 构建完整 Web 系统，Streamlit 可用于快速原型或辅助页面；
6. 评价重点是场景是否真实、流程是否清晰、工具调用是否可验证、数据是否可追溯、失败案例是否分析充分，以及 Git 协作是否完整。
